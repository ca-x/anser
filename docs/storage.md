# 存储与恢复

Anser 默认使用嵌入式 SQLite，启用 WAL、FULL 同步、外键与忙等待。SeaORM 用于业务实体读取和查询构造，事务队列与迁移集中在 `anser-store`，同一实例共用一个数据库连接池。应用层调用仓储方法，未来数据库适配器需要实现同一组事务语义。

| 写入边界 | 原子提交内容 |
| --- | --- |
| 接收一条消息 | Message、24 小时幂等记录、已选定顺序的路由和 Delivery、原生收件箱条目 |
| 领取路线 | 路由租约和所有权标记，恢复上次未回写的 Attempt |
| 开始某次投递 | 校验租约和账号、预约账号速率及熔断探测、创建 Attempt |
| 回写某次投递 | 完结 Attempt、Delivery 状态、账号熔断状态 |
| 释放路线 | 路由状态、下次调度时间、整体消息状态、可执行回调 |
| 退订 | 删除订阅、取消受影响的待发送路线、更新整体消息状态 |
| 兑换二维码 | 一次性消费哈希后的配对码、创建登录会话 |
| 双重验证登录 | 消费 TOTP 时间步或一次性恢复码、创建登录会话 |
| 启用或停用双重验证 | 更新验证状态和恢复码、撤销其他会话和未使用的配对码 |

入队使用有界缓冲，在短窗口内将多条请求合并为一次 WAL 提交。每条请求使用独立 savepoint，单条校验失败不回滚同批其他请求；外层事务提交成功后才返回 202。应用侧串行获取队列写权限，数据库仍负责跨连接的事务隔离。数据库锁内没有渠道网络请求或用户密码计算。并行 worker 按到期时间轮询，记录租约所有权标记，旧 worker 在失去租约或订阅取消后无法覆盖新状态。领取时回收被中断的尝试，已持久化成功的账号不会重新发送。如果下游已接收但进程在回写前崩溃，重试可能造成重复送达。这是跨进程和外部渠道的至少一次语义，入口幂等键只对 Anser 的接收事务去重。

路由决策持久化候选顺序、重试策略与绝对截止时间。账号配置更新后，下一次保留发送名额时读取最新配置。用户、账号、订阅与消息分别建表，凭据在账号及用户目标写入前使用 XChaCha20-Poly1305 加密，用户及 Topic 密码使用 Argon2 哈希。读取投递详情使用同一快照，收件箱以数据库序列排序。API 时间戳统一用 UTC 毫秒。

TOTP 种子使用同一主密钥加密，并绑定到用户和本次设置记录。恢复码只保存 SHA-256 哈希。已启用或等待确认的有效 TOTP 记录依赖原有主密钥。备份和恢复时请同时保留该密钥。

渠道启停的期望状态存入 `channel_settings`，缺省为启用。服务先提交期望状态，再执行运行时切换，启动时先恢复配置再接收请求和投递。临时缺少插件的构建会保留该插件的已存配置。渠道描述中的 `enabled` 是已保存的设置，`available` 是运行时能否接收调用，两者在运行时变更期间可能不同。切换失败可重新请求同一启停设置，查询接口仍会显示已保存的期望状态。停用的插件继续提供描述和配置 schema，更新账号凭据需要先启用相应插件完成配置验证。

后续 PostgreSQL 适配需要复验并发幂等、租约回收、旧 worker 隔离、跨状态快照、退订与在途发送竞争、用户间数据权限，以及升级迁移。SQLite 初始部署建议将数据库与密钥落在持久本地卷。备份应用运行中的数据库时，使用 SQLite 在线备份机制；迁移实例时同时带上主密钥。熔断和速率控制为单实例部署口径。

本地发布构建的入队测试使用 16 个并发客户端、3000 条独立幂等请求、临时 SQLite 和本地 ntfy mock，打开默认调度配置。3000 条均返回 202，吞吐约 1703 req/s，入队 P99 约 26.2 ms。此数据对应单机回环、单目标工作负载。

# Anser v0.1 Implementation Plan

**Goal** 交付完整 v0.1 自托管应用。首版含九个渠道、管理与发送 API、Rust SDK、内置 EUI 管理台、NSH 客户端和构建发布配置。

**Architecture** SQLite 事务同时写入消息、幂等记录与发送计划。调度以路由组为单位领取带所有权标记的租约，发送不占持有写锁。单个渠道结果与 Attempt 同事务回写，进程恢复时保留已经成功的投递。

**Spec** 用户提供的《雁字 Anser 产品需求文档 v0.1 草案》及会话中确认的渠道、参考项目和技能约定。

- [x] 渠道实现与本地协议验收。各渠道独立 feature，通过 rutis 注册；覆盖认证、消息适配、错误分类和网络边界。
- [x] 数据与安全。SQLite 升级迁移、API Key 作用域与轮换、账号和订阅目标凭据加密、管理接口与游标。
- [x] 可靠投递。入口幂等、路由计划、并发广播、租约回收、重试/TTL、退订取消、重放与回调。验证进程恢复及并发重复请求。
- [x] 产品入口。统一 REST/OpenAPI、Rust SDK、NSH TSX 管理及发送界面、部署配置。
- [x] 本地发布验证。Rust 格式、Clippy、测试、依赖审计、系统启动与 Linux/NSH 打包检查。
- [ ] 对外发布验收。执行标签工作流并核对多平台制品、真实外部渠道和移动端签名包。

直接投递与主题发布采用同一路由规则。已有订阅的主题按匹配订阅分别生成路由组，拥有专属目标的订阅覆盖主题目标；请求中存在显式渠道时，显式渠道优先。无订阅的主题按主题策略投递一次。单空间保持数据库空间标识。P2 增强按 PRD 分开列示。


服务端支持环境变量初始化管理员、用户登录、按用户隔离的 Topic 订阅、Topic 密码和一次性二维码配对。原生收件箱记录服务端发布和客户端之间的通知。EUI 登录路由为 `/login`，管理台为 `/admin`。NSH 独立打包，使用原生组件和操作系统的配对链接交接。

已验证本地的失败重试、重启续投、退订取消、广播 `any` 与独立重试、TTL 死信、并发幂等、租约隔离，以及保护主题和一次性配对。存储约束见 [存储与恢复](../storage.md)。

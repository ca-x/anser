# 雁字客户端设计规范

客户端使用 NSH、TSX 与 Tailwind。任务从发送一条通知开始，投递详情负责解释系统选中了哪个账号、哪次尝试失败、何时会重试。Logo 用于连接页和应用图标，工作区以内容和系统控件为主。

## 页面与布局

| 页面 | 主要任务 | 关键交互 |
| --- | --- | --- |
| 连接 | 填服务器地址与 API Key | 行内校验地址，提交时立即显示连接状态，区分无法访问、未授权和权限不足 |
| 发送 | 选择 Topic 或显式渠道，填写并投递 | 固定主操作位置，显示最终目标和消息格式，收到 202 后可进入投递详情 |
| Topic | 创建主题和管理订阅 | 列表支持键盘选择，详情展示默认策略和订阅目标，退订前说明待发送任务也会取消 |
| 渠道账号 | 检查可用性、启停和测试 | 显示账号名、渠道和状态，危险操作与测试发送分开，测试结果保留在原位 |
| 投递详情 | 定位失败原因与重试时间 | 先显示整体状态，再依账号展开 Attempt，重试时间用绝对本地时间并可辅以倒计时 |

桌面用固定宽度侧栏和可伸缩内容区，消息详情以独立区域呈现。手机使用系统导航和单列页面，键盘出现时保留输入框及主操作的可达性。Web 根据实际视口和输入能力切换布局。

## 视觉系统

保留 Logo 的暖铜色，用于主操作和焦点。正文与表格采用系统字体，正文 15、辅助文字 13、组标题 19、页标题 26。密度以 4、8、12、16、24、32 的间距尺度组织。桌面紧凑输入控件高至少 32，触控交互区域至少 44。圆角用于控件和容器层级，控件 6、分组 10、浮层 12。

颜色集中在语义主题定义中，页面、overlay 和复用控件引用语义 token。

在 `nsh/base` 之上维护项目控件，覆盖按钮、输入框、选择器、状态、导航、确认和通知反馈。错误文字关联输入控件，状态包含文字及图标。采用清晰的键盘顺序和可见焦点环。窄窗口使用换行和分栏收起，发送和退订的动作标签始终可见。

## 动效和反馈

- 按压立即显示反馈。发送期间保留标题和正文，主操作显示提交中。连接、提交和请求失败都保留可恢复状态。
- 键盘导航、列表选择和投递状态刷新即时更新。偶发的详情浮层采用短淡入和轻微位移，并可在退出和再次进入时中断。
- 减少动态效果时保留焦点、状态文案和层级变化。详情时间轴和数据行位置保持稳定。

## 连接与凭据

TSX 通过 `fetch` 使用公开 HTTP API。自托管地址需要通过 NSH 的网络 capability 授权。普通 NSH Storage 只有应用隔离保证，API Key 默认仅存于会话内存。持久会话需先确认原生平台提供的安全凭据存储。Web 使用服务端显式配置的 CORS 来源。

## 验收

在桌面和手机分别检查键盘、触控、窄屏、两套主题和减少动效。用真实 Anser API 验证连接失败、鉴权错误、发送入队、广播部分成功以及超过 TTL 的投递详情。交互和组件遵循 nsh-design-guides，使用 ui-ux-pro-max、frontend-design、apple-design、emil-design-eng 与 animate 评审视觉、状态及动效。
